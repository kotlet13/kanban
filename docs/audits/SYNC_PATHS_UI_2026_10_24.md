# Izvorni audit poti sinhronizacije: UI, stanje in lokalne projekcije

Datum: 24. oktober 2026. Podlaga: trenutni izvor r6 in že shranjeni dnevniki; sam audit ne izvaja aplikacije, testov, gradenj, HTTP ali dejanj na napravah/strežniku. To je samostojen fragment za glavni audit. Dokaz o obstoju poti ni meritev njene pogostosti. Število rebuildov, lokalnih branj in HTTP zahtevkov so tri različne stvari.

## Glavne ugotovitve

1. Običajna sinhronizacija ima en foreground urnik z 30-sekundnim preverjanjem in backoffom. To **ne zajame vseh omrežnih delov aplikacije**: account protection, recovery, povabila, dovoljenja financ, dokumentni gateway in odpiranje notification targeta imajo lastne neposredne bralne poti. Njihov lokalni busy guard ne pomeni skupne mrežne serializacije.
2. Takojšnja zahteva po syncu je vezana na `CollaborationController._edit`. Shrambi skupnih idej in vrta ter lokalni/personal organizer pišejo tudi po drugih poteh. Na teh pregledanih poteh ni istega klica `schedule.localEdit()`; trajno delo obstaja, vendar takojšnjega prenosa iz tega izvora ni mogoče obljubiti. Gre za vrzel v enotnem sprožilcu, ne dokaz izgube podatkov.
3. r6 že preprečuje staro široko ponovno nalaganje repozitorijev ob vsaki statusni objavi: primerja vsebinske podpise domen in ohranja identitete nespremenjenih projekcij. Še vedno obstajajo širši lokalni porabniki celotnega `collaborationProvider`: agregat vseh prostorov, ideje vseh prostorov, idejni asset provider, izračuni opomnikov in OS notification coordinator.
4. Odpiranje obstoječega task editorja je zdaj lokalno in finance choices tečejo po prvem prikazu. Odprtje finančnega entry editorja še vedno čaka finance choices; dokumentna branja so praviloma najprej oddaljena in imajo lokalni fallback šele ob napaki `network`.
5. Odprtje finančnega planiranja in minute/reconcile za lokalna obvestila lahko materializirata ponovitve. To je poslovno delo, ne samo branje. No-op choices/materialization ne sme več ustvariti lažne sync zahteve; dejanske spremembe pa jo lahko.
6. r6 zahteven native tok je STOP3 zaradi 429. Dnevniki brez argumentov, account/lease/phase identitete ne dokazujejo, koliko zahtevkov je res identičnih ali kateri listener je neposredni povzročitelj. Popravkov ali ponovitev ta audit ne izvaja.

## Oznake in obseg

- **L**: lokalni SQL/datoteka/izračun/rebuild/osvežitev projekcije; samo to ni HTTP.
- **N**: branje prek transporta/crypto adapterja; lahko vključuje več podpisanih preverjanj.
- **W**: poslovna ali tehnična mutacija, trajna vrsta/draft/ključni journal; ni nujno takojšen HTTP.
- **S**: zahteva običajnemu sync koordinatorju.
- **P**: OS/SDK obvestila, timezone ali lifecycle; ni sam po sebi content sync.

Kombinirane oznake pomenijo različne veje iste družine. Razvrstitev neposrednega UI klica sledi pregledani implementaciji; ni trditev, da vsaka izvedba nujno pošlje zahtevek. Network adapter lahko uporabi obstoječe preverjeno branje, lokalni cache ali prekine pred HTTP. Varnostni fresh mutation preflight se ne šteje kot odveč samo zato, ker ima isto ime kot prejšnje branje.

## Osnovni graf in meje koordinatorja

```text
build / foreground resume / reconnect ali explicit manual
    → CollaborationController / CollaborationSyncSchedule
    → repository.syncNow → account.changes → samo prizadete domene/odvisnosti
    → verified durable apply → refreshLocal → repo.changes
    → AsyncData state + domenski personalChanged → lokalni repozitoriji/projekcije

CRUD prek CollaborationController._edit
    → lokalni action/outbox + refreshLocal → schedule.localEdit + refresh

Idea/GardenController ali OrganizerController
    → lasten repository/storage → lokalna sprememba/outbox + spremembe projekcije
    → na pregledani poti ni istega controller._edit sync-demand klica

neposredni UI/recovery read
    → repository/crypto service/context.call
    → lastni verified-operation lease/fresh guards
    → ni nujno del zgornjega 30-sekundnega urnika
```
